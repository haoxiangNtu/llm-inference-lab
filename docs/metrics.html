vLLM 是什么

vLLM 是加州伯克利 2023 年开源的大模型推理引擎，现在是开源模型部署的事实标准。名字里的 v 来自"虚拟内存"：它的核心发明 PagedAttention 把操作系统的分页思想搬到了显存管理上，把 KV cache 切成小块按需分配，显存利用率从传统做法的 20% 到 40% 提高到 90% 以上。

在一次部署里它负责：把权重加载并切到多张卡上（张量并行、流水线并行、专家并行），管理 KV cache，把同时到达的请求合批送进 GPU（连续批处理），对外提供 OpenAI 兼容的 HTTP 接口。vllm serve 启动服务，vllm bench serve 是它自带的压测客户端。同类工具还有 SGLang、TensorRT-LLM、llama.cpp。

推理的两个阶段

Prefill 一次性读完提示词，所有 token 并行计算，矩阵乘的规模是"token 数 × 隐藏维度"，GPU 的算力被喂饱，瓶颈是算力。Decode 逐个生成输出 token，每生成一个都要把全部激活权重和 KV cache 从显存读一遍，算力大量闲置，时间花在搬数据上，瓶颈是显存带宽。两个阶段性质不同，所以性能指标也分开测。

A800 的显存带宽是 2 TB/s。一个每 token 激活 18B 参数、FP8 存储的模型，4 卡分摊后每卡每步要读 4.5 GB，理论下限约 2.3 ms。实测 GLM-5.3-Flash 的 TPOT 是 20 ms，差距来自内核效率、流水线气泡和通信开销。原理实验台第 2 站可以拨动这些参数看效果。

压测时用固定长度的随机输入并强制生成到指定长度（ignore_eos），是为了让不同模型的数字可比，不受它们"话多话少"的影响。并发 1 / 4 / 8 / 16 / 32 的曲线比单个数字更有信息量：曲线先陡后平的拐点就是算力墙。

这套评测的局限

  • 样本量小，准确率有正负 3 到 5 个点的抖动，看趋势别抠小数。
  • 同一套脚本下的横向比较有意义，和官方榜单不可直接比：提示词、思考模式、判分规则、token 预算都不同。
  • 性能数字绑定部署配置：卡数、并行方式、max-num-seqs、KV 精度都会改变曲线，报告里都标了配置。
  • 图形题只是合成图，不代表真实视觉能力。

脚本都在仓库的 bench/ 目录：quality.py 跑质量，perf.sh 跑性能矩阵，report.py 汇总。
